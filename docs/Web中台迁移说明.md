## 本次已实现的前端模块

| 模块 | 页面与操作 | 数据口径 |
| --- | --- | --- |
| 产线状态 | 九台产线状态矩阵、检测点环图、健康排行、详情入口、30 秒同步 | 直接使用 `/LineInfo/LineInfo` 实时数据 |
| 缺陷数据采集 | 品牌/类型/相机查询、分页、创建、删除、样本卡片、进入标注 | 总数取服务端；图表只统计当前页 |
| 基础缺陷集 | 训练/验证用途切换、品牌/类型/相机筛选、分页、查看标注 | 原始列表按条件过滤后分页 |
| 图片工作台 | 图片分页、缩放、矩形框选、类别选择、坐标编辑、保存、删除、未保存提醒 | YOLO 归一化坐标；保留已有标注 |
| 产线图片采集 | 指定日期范围采集，自动转换 camera0 → 0 | 使用客户端 DownLoadNgImagesRequest 契约 |
| 辅助打标 | 选择匹配模型、提交辅助标注请求 | 仅提示任务已提交，完成后刷新查看 |
| 模型库 | 查询、分页、创建者补全、训练样本检视、参数读取/保存、删除及 409 强制删除二次确认 | 保留服务器模型权限控制 |
| 训练任务 | 选择数据集、配置代数/批次、名称检查、提交、状态轮询、失败记录删除 | 不把 HTTP 成功当成训练完成 |
| 验证任务 | 选择模型与数据集、名称检查、提交、分页、状态轮询、结果图片对照、删除 | 仅验证完毕开放结果 |
| 标准缺陷 | 搜索/筛选、样例图预览、唯一文件名上传、新增/编辑/删除、等级分布 | 全部缺陷列表客户端筛选分页 |
| 打标缺陷 | 标签列表、新增、缺陷标签关联、受限删除、分布图 | 暂沿用 WPF 返回列表下标；不擅自转成数据库 ID |
| 质量分析 | 产线/日期/班次查询、高频缺陷、等级占比、累计占比、CSV 导出 | 检出次数不等于不合格产品数量 |

所有新模块使用独立 Bearer 请求封装，避免现有大屏历史 Basic/Blade 逻辑影响中台接口。不使用固定用户 ID；不把登录记录 ID 当成用户 ID。API 错误与无数据分别显示。没有向生产代码加入模拟业务数据。

## 架构与测试

新代码在 `src/workspace`，按数据集、标注、缺陷、模型、质量模块拆分。中台样式独立于大屏 rem 缩放，卡片/图表提供过渡动画及减少动态效果支持。图表资源使用 ResizeObserver，卸载时销毁；训练/验证在页面隐藏或离开时停止轮询，失败后退避。

- `npm run build`：生产构建。
- `node --test tests/workspace.test.mjs`：用户 ID、图片代理地址、分页、YOLO 坐标与分布统计测试。

## 图片地址代理

标准样例图 `/images` 与现有 `/ngimages`、`/detectedimages` 一样转发至 `BACKEND_URL`。

中台其他服务器图片路径统一转换为 `/backend-assets/<原路径>`，代理只转发至固定后端并去除 `/backend-assets` 前缀，不接受浏览器指定其他代理主机。若新版返回的是独立对象存储的签名 URL，应由服务端提供下载代理或进一步按真实契约适配，不应假定相同路径在当前后端可访问。

若改用 IIS/Nginx，应同步配置上述代理和重写。配置仍是开发 `.env.development`、生产 `.env.production`。
